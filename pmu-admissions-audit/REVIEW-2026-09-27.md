## 5. Post-review fix — encoding (reported by the owner from a phone)
- **Symptom:** in the mobile file preview, the Arabic appeared as Latin-1 mojibake (e.g. `Ù…Ø´Ø±ÙˆØ¹`).
- **Cause:** the built plan was a fragment with no `<!doctype>`, no `<meta charset>` and no `<html lang>`. Desktop browsers guessed UTF-8; the phone viewer fell back to windows-1252. The plan was also missing its own page language, the same defect as F-29.
- **Fix:** `src/build_plan.py` now emits `<!doctype html><html lang="ar"><meta charset="utf-8">` plus a viewport meta tag, and writes a UTF-8 BOM.
- **Verification:** the file was served with a deliberately wrong `charset=windows-1252` header. The old build reproduced the owner's mojibake; the new build decodes as UTF-8 and renders correctly at 390 px.
